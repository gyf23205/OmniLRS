# Yamcs ground station — perseverance rover

A local Yamcs instance that acts as the ground station for the perseverance rover running in
OmniLRS. Rover state is downlinked into the Yamcs parameter archive at a low rate (1 Hz, against a
30 Hz physics loop) and high-level commands are uplinked back from the Yamcs web UI.

## Start it

```bash
cd yamcs_server
docker compose up -d --build     # web UI: http://localhost:8090
docker compose logs -f           # watch
docker compose down              # stop
```

Rerun with `--build` after regenerating the mission database.

## Run the simulator against it

```bash
# inside the Isaac Sim container
/isaac-sim/python.sh /workspace/omnilrs/my_files/src/run_perseverance.py --yamcs
/isaac-sim/python.sh /workspace/omnilrs/my_files/src/run_largescale_perseverance.py --yamcs
```

Without `--yamcs` the scripts run exactly as before, so a stopped ground station never blocks
ordinary use.

## What talks to what

```
                 Yamcs (this container, host network)
                 ┌──────────────────────────────────────┐
   operator ────▶│ web UI :8090   parameter archive     │
                 └──────┬──────────────▲────────────────┘
              udp-tc-out│              │ set_parameter_value
                  :10025│              │
     Isaac Sim   ┌──────▼──────────────┴────────────────┐
     container   │ CommandsHandler ─▶ PerseveranceCommander    (prints the command)
                 │ IntervalsHandler ─▶ PerseveranceTransmitter (downlinks state)
                 └───────────────────────────────────────┘
```

Both containers run with `--network=host` (see `omnilrs.docker/run_docker.sh`), so they reach each
other over loopback with no port mapping.

## Files

| Path | Role |
|---|---|
| `Dockerfile` | Strips the demo mission out of the Yamcs example image and adds ours |
| `etc/yamcs.yaml` | Server-wide config; declares the `omnilrs` instance |
| `etc/yamcs.omnilrs.yaml` | Instance services, MDB loader, the TC UDP link |
| `etc/processor.yaml` | The `realtime` processor, including `LocalParameterManager` |
| `../cfg/mdb/perseverance.xml` | Mission database, generated by `scripts/generate_perseverance_mdb.py` |
| `../cfg/mode/Yamcs.yaml` | Where the simulator finds this server |
| `../cfg/controller/perseverance-controller.yaml` | Downlink rate + the parameter/command name maps |

## Design notes

**No TM packet stream.** The rover pushes *software parameters* over the API rather than sending
TM packets, so the MDB declares no containers. A `tm` stream or an `XtceTmRecorder` therefore makes
Yamcs refuse to start with *"MDB does not have a root sequence container"*. Both are deliberately
absent.

**Every parameter is `dataSource="local"`.** That is what makes `processor.set_parameter_value()` —
the call behind `YamcsTMTC.transmit_to_yamcs` — legal, and it is why `LocalParameterManager` must
be in the realtime processor.

**No command postprocessor.** `GenericCommandPostprocessor` without `errorDetection` adds nothing
to the packet, so the datagram is exactly the ASCII command name followed by its arguments — the
layout `MdbParsingService.decode_tc_payload` matches on. A postprocessor that prepended a header
(`IssCommandPostprocessor`, for example) would break decoding.

**One MDB, two readers.** `cfg/mdb/perseverance.xml` is copied into the image at build time and is
also read directly by `MdbParsingService` in the simulator, so the two can never drift.

## Regenerating the mission database

```bash
pip install yamcs-pymdb
python3 scripts/generate_perseverance_mdb.py
cd yamcs_server && docker compose up -d --build
```
